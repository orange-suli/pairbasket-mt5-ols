# PairBasket v10.0：双 Spread 与优化指标说明

## 1. 本次改动目标

本版本在 v9.1 线性加仓版基础上增加两项能力：

1. **完成优化后导出每个参数组合的自定义风险指标**，用于比较不同策略/参数，不只看最终净利润。
2. **增加第二种 Spread 模型：rolling OLS 的 log-price 残差**，并保留原有 SMA 相对偏离 Spread。两种 Spread 可直接作为 MT5 优化参数一起测试。

原有的 Basket 方向、线性阶梯加仓、回归后盈利平仓、冷却期、M15/M30/H1 优化逻辑继续保留。

---

## 2. Spread 模型

### 2.1 模型 0：原有 SMA Relative Spread

参数：

```text
InpSpreadModel = 0
```

公式：

```text
Spread_t = ln(P1_t / SMA1_t) - ln(P2_t / SMA2_t)
```

其中 SMA 使用前 `InpLookBack` 根已完成 K 线。

随后仍按当前程序计算：

```text
Z_t = (Spread_t - rolling_mean(Spread)) / rolling_std(Spread)
```

Z 的历史窗口由 `InpLookBack` 控制。

### 2.2 模型 1：rolling OLS log residual Spread

参数：

```text
InpSpreadModel = 1
```

对应公式：

```text
log(P1_t) = alpha_t + beta_t * log(P2_t) + epsilon_t
Spread_t  = epsilon_t
Z_t       = ZScore(Spread_t)
```

实现细节：

- `y = log(Symbol1)`
- `x = log(Symbol2)`
- 用前 `InpRegressionLookBack` 根**已完成 K 线**拟合 OLS：

```text
beta  = Cov(x, y) / Var(x)
alpha = mean(y) - beta * mean(x)
```

- 当前 bar (`shift=0`) **不参与回归拟合**，只用来计算当前残差：

```text
Spread_t = log(P1_current) - alpha - beta * log(P2_current)
```

这样避免使用当前未完成 bar 反过来影响 alpha/beta。

- 得到 residual Spread 后，仍沿用 EA 原来的 Spread 历史与 Z-Score 模块，`InpLookBack` 是 residual Z-Score 的历史窗口。

因此模型 1 有两个窗口：

```text
InpRegressionLookBack  -> alpha / beta 的回归窗口
InpLookBack            -> residual Spread 的 Z-Score 窗口
```

第一轮测试建议先固定 `InpRegressionLookBack=60`，不要同时优化太多维度。

## 3. MT5 中如何一次测试两种 Spread + M15/M30/H1

在“完成优化”或“遗传优化”的 Inputs 页面勾选：

| 参数 | Start | Step | Stop | 含义 |
|---|---:|---:|---:|---|
| `InpSpreadModel` | 0 | 1 | 1 | 0=SMA Relative；1=OLS residual |
| `InpTimeFrame` | 0 | 1 | 2 | 0=M15；1=M30；2=H1 |

因此仅 Spread × 周期就会产生：

```text
2 × 3 = 6 组
```

然后可以再叠加：

```text
InpZScoreOpen
InpAddZStep
InpMaxAddCount
InpAddLotStep
```

建议第一轮不要同时优化 `InpRegressionLookBack`。原因是它只对 OLS 模型有效；如果同时在 SpreadModel=0/1 的大网格中优化，会在 SMA 模型上产生大量完全重复的 Pass。

## 4. 新增优化统计参数

```text
InpExtremeZThreshold = 3.0
```

定义“极端 Z”：

```text
|Z| >= InpExtremeZThreshold
```

如果设置 `<=0`，程序自动使用 `InpZScoreOpen` 作为极端 Z 阈值。

```text
InpExportOptimizationCSV = true
InpOptimizationCsvName   = PairBasket_v10_OptimizationMetrics.csv
```

完成优化后，EA 使用 `FrameAdd / OnTesterDeinit` 汇总每个优化 Pass，并输出 CSV。

默认位置：

```text
MetaTrader Common Data Folder\Files\PairBasket_v10_OptimizationMetrics.csv
```

运行完成后，Experts/Journal 会打印完整实际路径。

## 5. CSV 中的风险指标定义

### MaxAccountProfit

测试期间：

```text
max(Equity - InitialBalance)
```

使用 **Equity** 而不是 Balance，因此包括未实现浮盈。

### MaxAccountLoss

测试期间相对初始账户余额的最大亏损绝对值：

```text
max(InitialBalance - Equity, 0)
```

CSV 中使用正数表示亏损规模，例如 `3250` 表示最大曾亏损 3250 个账户货币单位。

### WorstBasketLoss

单个 Basket 生命周期内最大的权益亏损绝对值。

Basket 首仓前记录账户 Equity；Basket 存续期间逐 Tick 计算：

```text
BasketPnL = CurrentEquity - EquityBeforeBasketEntry
```

因此包含：

- 浮盈浮亏
- 点差
- 开平仓佣金对 Equity 的影响
- Swap
- 已实现的本 Basket 损益

测试器中每个 Pass 为单 EA 策略环境，所以此定义适用于当前优化场景。

### MaxEquityDrawdown

测试期间的最大权益峰谷回撤：

```text
PeakEquity = max(历史 Equity)
Drawdown   = PeakEquity - CurrentEquity
```

输出金额和百分比两个版本：

```text
MaxEquityDrawdown
MaxEquityDrawdownPct
```

### LongestBasketHoldHours

测试中观察到的单个 Basket 最长持仓时间。

如果数据结束时还有未结束 Basket，也计入最长持仓时间，避免低估尾部风险。

### AvgBasketHoldHours

所有已完成 Basket 的持仓时间，加上数据结束时仍未结束 Basket 已经持有的时间，再除以观察到的 Basket 数量。

因此一个长期未回归、一直挂到测试末尾的 Basket 不会被平均值忽略。

CSV 同时输出：

```text
ActiveBasketAgeHoursAtEnd
```

用于识别测试结束时仍未退出的 Basket。

### MaxExtremeZHours

连续满足：

```text
|Z| >= InpExtremeZThreshold
```

的最长持续时间。

### AvgExtremeZHours

所有极端 Z episode 的平均持续时间。

### Sharpe

直接读取 MT5 Strategy Tester 的：

```text
TesterStatistics(STAT_SHARPE_RATIO)
```

`OnTester()` 同时返回 Sharpe，因此如果优化 Criterion 选择 **Custom max**，MT5 会按 Sharpe 从高到低比较参数组合。

### NetProfit / ProfitFactor

同时从 MT5 标准测试统计中导出，方便和自定义风险指标一起筛选。

## 7. 建议第一轮完整优化参数

为了先判断 Spread 和周期，建议第一轮使用：

```text
InpSpreadModel       0 -> 1, step 1
InpTimeFrame         0 -> 2, step 1
InpZScoreOpen        1.5 -> 3.0, step 0.25
InpAddZStep          0.5 -> 1.5, step 0.25
InpAddLotStep        0.01 -> 0.03, step 0.01
```

先固定：

```text
InpLookBack           = 60
InpRegressionLookBack = 60
InpMaxAddCount         = 7
InpExtremeZThreshold  = 3.0
```

之后根据结果缩小范围，再单独研究 LookBack、RegressionLookBack 和 MaxAddCount。

---

## 8. 看结果时建议不要只按净利润排序

当前策略存在逆势加仓，所以尤其建议同时筛选：

```text
NetProfit 高
Sharpe 高
MaxEquityDrawdown 低
WorstBasketLoss 低
LongestBasketHoldHours 可接受
MaxExtremeZHours 可接受
ActiveBasketAgeHoursAtEnd = 0 或较小
```

如果一组参数净利润很好，但 `WorstBasketLoss`、`MaxEquityDrawdown` 或测试末尾未结束 Basket 非常大，应视为高尾部风险组合，而不是直接作为最佳参数。
